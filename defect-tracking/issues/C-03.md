### C-03: CMS986 malnutrition score-component authoring mismatch (shared across both engines)

- **Symptom**: 120 test cases / 822 cells fail. Expected values for `Group_N:Measure Population Observation`
  carry the **percentage score** components from `define function "Measure Observation Total Malnutrition Care Score as Percentage"(...)`
  (`input/cql/CMS986FHIRMalnutritionScore.cql` line 300): values like 1, 2, 3, 4, 50, 75, 100.
  Actual results (CMS engine) and QI-Core baseline both carry `Group_N:Measure Observation` (the **count** of qualifying observations) = 0 in every Group_x for every case.
- **Mechanism**: the measure resource (`input/resources/measure/CMS986FHIRMalnutritionScore.json`) uses
  `display: "Measure Observation"` (singular) per Group, while the fixture-authored MeasureReports
  (`input/tests/measure/CMS986FHIRMalnutritionScore/<case>/MeasureReport-*.json`) use `display: "Measure Population Observation"`
  with a SCORE value, never implemented via the current measure resource wiring. The CQL has both semantics
  defined (`Measure Observation 1/2/3/4` as functions, but no `define` returns them per patient); the
  `Measure Observation Total Malnutrition Components Score` and `... as Percentage` functions compute scores
  but are **never invoked** from a population criterion. Both engines therefore cannot emit score rows, only count rows.
- **Evidence** (`scripts/comparison/engine_shared_issues.py --measure CMS986FHIRMalnutritionScore`):
  * `shared`: 494 cells (both engines return 0 vs expected score 1/2/3/4/50/75/100) - measure-resource / fixture-MR authoring mismatch.
  * `cms-only`: 6 cells (`a4f53b12`, Measures Population Exclusion 0 vs QI-Core 1, all 6 groups) - HHS ServiceRequest `us-quality-core-servicerequest` profile retrieve gap (already covered by E-17).
  * `qicore-only`: 0 cells.
  * `conflicting` / `incomplete`: 0.
  * Overall shared% of not-passing: **98.8%**.
- **Workaround**: none shipped. Candidates: (1) re-author fixtures' MeasureReports to remove orphan `Measure Population Observation` rows (silence in expected_results.csv); (2) wire `Measure Observation 1/2/3/4` score-component functions as separate `define`s in the CQL and add measurement-observation population criteria in the measure resource returning percentage values; (3) change group mapping such that the existing `Measure Observation` count population is renamed to align with the expected MR rows. Deferred pending content decision.
- **Status**: **Confirmed** (2026-09-04, `shared%` analysis). Not remediated.
