### F-10: CMS1264 fixtures keyed to measurement period 2027 instead of 2026

- **Symptom**: 57 of 58 CMS1264 test cases fail. Expected populations (`exp=1`, some `exp=2`) evaluate 0 because every encounter/condition/claim/service-request is dated 2027/2028 while the engine runs the 2026 measurement period (global `input/tests/config.json` MP override `@2026-01-01T00:00:00.000Z ../ @2027-01-01T00:00:00.000Z)`); `9bac5045` fails in reverse (`exp=0, act=1` - its encounter ends 2026-12-31, inside @2026). Both engines agree: the authoritative QI-Core actuals show the identical pattern (136 `exp:1->act:0`, 13 `exp:2->act:0`, 3 `exp:0->act:1`) on the same upstream fixtures; the QI-Core source repo's own CQL default MP for CMS1264 is @2026 while its test data is 2027-keyed. This is a data-year anomaly in the upstream package, not an engine defect.

- **Precedent**: sibling E-CAT measure CMS1244 (same patient GUIDs, 46 shared cases) carries the identical scenario already re-keyed to 2026 in dqm-content-qicore-2025 by commit `3c756c47` ("updates CMS1244 test case dates to align with 2026 measurement period", 2026-01-16). Comparing shared case `c3284314` confirms the intended transformation: CMS1264 has Encounter periods `2027-05-01` / birthDate `2010-01-01` / MeasureReport period 2027, while CMS1244 has `2026-05-01` / `2009-01-01` / 2026. CMS1264 was missed by that commit. Repo convention: 71/74 measure resources effectivePeriod 2026, 83/84 CQL defaults @2026; only CMS1264 defaults @2027.

- **Fix (applied 2026-09-04)**: uniform -1 year shift of *every* date value across all 342 fixture files (653 date tokens) - encounters (incl. `location[].period`), `Patient.birthDate`, `Condition.recordedDate`, `Claim.created`, `ServiceRequest.authoredOn`, `Coverage.period`, and `MeasureReport.period` - preserving ages, prior-MP windows, and end-of-MP boundary behavior. Applied via `scripts/rekey_cms1264_fixtures_to_2026.py` (formatting-preserving, guarded on the MeasureReport `period.start`, idempotent; re-run reports 0 changes). Aligned CQL default MP `@2027->@2026` to match the QI-Core source repo and the 83/84 repo norm. Population counts unchanged - regenerated `expected_results.csv` is byte-identical to the committed baseline, so all 174 CMS1264 expected rows are preserved.

- **QI-Core note**: `qicore-2025-actual-results.csv` is a locked, older engine-output baseline marked "do NOT regenerate"; it still carries the stale 2027-keyed CMS1264 rows, so the informational cross-engine column will show CMS1264 as CMS-pass / QI-Core-fail after this fix - a pre-existing baseline artifact, not a regression.
