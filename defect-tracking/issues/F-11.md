### F-11: non-canonical UCUM quantity system crashes the library (CMS347 `6da189af`)

- **Symptom**: CMS347 `6da189af` reports **Missing Results** for all 4 groups (20 cells). The engine
  trace shows `FHIRHelpers.ToQuantity.InvalidFHIRQuantity: Invalid FHIR Quantity code: mg/dL
  (https://ucum.org|mg/dL)` — the LDL Observation `dce97708` (LOINC `13457-7`) sets
  `valueQuantity.system` to `https://ucum.org`; the canonical UCUM system is
  `http://unitsofmeasure.org`. The throw is uncaught, so the library evaluates nothing → every group
  Missing.
- **Evidence**: all 41 other CMS347 LDL observations use the canonical system and evaluate cleanly;
  a repo-wide sweep found only 3 fixtures using `https://ucum.org` — this one plus 2 CMS69 BMI
  Observations (`7b34e64e`, `45b1ce40`) which are latent (the engine's BMI profile retrieve is empty
  on CMS69 today, so the throw never fires). Fixed all three.
- **Fix (applied 2026-09-04)**: substitute `valueQuantity.system` → `http://unitsofmeasure.org` via
  `scripts/fix_cms347_fixture_data.py` (idempotent, formatting-preserving). CQL and MeasureReport
  (expected) values unchanged.
- **Category**: resource / fixture data.
- **Status**: fix applied; engine verification pending (expected: `6da189af` resolves, +20 cells).
