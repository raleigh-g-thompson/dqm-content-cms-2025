### C-02: CMS157 — cancer-diagnosis mismatches — CONFIRMED stale/truncated local valueset expansion, now repaired

- **REVISED 2026-09-07 — root cause CONFIRMED systemic**: the earlier claim that the
  “Cancer” valueset (`2.16.840.1.113883.3.526.3.1010`) is SNOMED-only is **wrong**.
  The valueset is a mix of SNOMED CT and ICD-10-CM codes, composed of sub-valuesets
  `2.16.840.1.113883.3.526.2.1078` (SNOMED + ICD-10-CM, incl. `C00.0`, `C00.3`,
  `C18.6`, `C22.0`, `C34.01`, `C40.00`) and `2.16.840.1.113883.3.526.2.1079`
  (SNOMED, incl. `80914001`).
- **Symptom**: 19 failing test cases — 17 carry ICD-10-CM cancer diagnoses
  (`C00.0`, `C00.3`, `C18.6`, `C22.0`, `C34.01`, `C40.00`), 2 carry SNOMED `80914001`
  (e.g. fixture `055640ae.../Condition-8f04d38c...`). The (E-13-sound) base
  `[Condition: "Cancer"]` retrieve matches none of them → 19 residual mismatches.
- **Root cause (confirmed, systemic)**: the committed local valueset files each
  stored only the *first page* (1000 codes) of a paged `$expand`
  (`expansion.parameter` `count:1000, offset:0`), even though `expansion.total`
  declared the true count. `scripts/comparison/audit_valueset_cache.py` found **45
  truncated files** across all measures (not just CMS157) plus 1462 more that were
  complete but retained the paging artifact. The IG Publisher's terminology cache
  (`input-cache/txcache/vs-*.json`) holds the complete expansions.
- **Evidence (2026-09-07)**: the committed local expansion
  (`ValueSet-2.16.840.1.113883.3.526.3.1010-20200306.json`) contained 1000 SNOMED
  entries of the declared `total: 7563`, with **no** ICD-10-CM codes and **not even**
  the SNOMED `80914001`. Both sub-valueset files
  (`ValueSet-2.16.840.1.113883.3.526.2.1078-20250130.json`,
  `ValueSet-2.16.840.1.113883.3.526.2.1079-20250131.json`) DO contain those codes.
  All 7 unique failing codes are present in the sub-valuesets but absent from the
  committed expansion.
- **Resolution**: `scripts/comparison/repair_valueset_cache.py` copied the complete
  txcache expansions into the committed files — **42/45 repaired**
  (`2.16.840.1.113883.3.526.3.1010` now `total: 7541`, full `contains`, no paging
  param; all 7 failing codes present). 3 remain unresolvable from cache:
  `...3.464.1003.110.11.1151` (version drift — cache has 20251016 vs committed
  20250205), `...3.600.1.1623` and `...3.600.1.1624` (no txcache entry;
  non-NLM/legacy OIDs).
- **Verification (2026-09-07 21:14 engine re-run)**: CMS engine now passes **63/0** on
  CMS157 — all 19 formerly-failing cases return exactly the expected counts
  (`compare_results.py` / `discrepancy_report.md`). C-05's parallel
  'fixture authoring mismatch' diagnosis is retracted (folded here).
- **QICore side (2026-09-08)**: the 42 repaired files were mirrored into `dqm-content-qicore-2025`
  (verified byte-identical source) and the QI-Core engine was re-run there (all 3964
  `TestCaseResult-*.json` freshly evaluated 2026-09-08). The regenerated baseline
  `qicore-2025-actual-results.csv` now matches expected on **all 63/63 CMS157 cases**
  (CMS157 row: 63 / 0 | 63 / 0 | Match on both engines). The 46 residual `qicore-only`
  cells are gone. CMS157 is fully resolved on both engines.
- **Category**: terminology / stale-content (confirmed), not an engine issue.
