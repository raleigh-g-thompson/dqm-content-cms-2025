### F-08: CMS69 test data mis-attributes BMI & pregnancy-status Observations

- **Symptom**: 17 CMS69 test cases mismatch (16 `Numerator 1→0` + 1 `Denominator Exclusion 1→0`). The 16 Numerator cases each carry one qualifying BMI Observation (LOINC `39156-5`, `status final/amended/corrected`, value >0 within MP) profiled `us-quality-core-observation-screening-assessment`; e25fc2f1 carries a pregnancy-status Observation (LOINC `82810-3`, SCT `77386006` Pregnant) under the same profile.
- **Root cause**: the QI-Core → US Quality Core conversion re-attributed CMS69 test data to the USQC profile, but the measure CQL retrieves via `[USCore.BMIProfile]` (line 69) and `[USCore.ObservationPregnancyStatusProfile]` (line 186) — the engine's profile-based retrieve matches **only** the exact declared US Core profile (verified 1:1 across repo: CMS1017 5/5, CMS1218 1/1, CMS69 0/0). **Engine is correct; data is wrong** (same family as the E-17 / `ObservationScreeningAssessment` profile-retrieve analysis, but attribution is DATA-side, not engine-side).
- **Fix (applied 2026-09-04)**: re-attribute the 16 BMI Observations → `http://hl7.org/fhir/us/core/StructureDefinition/us-core-bmi`; re-attribute e25fc2f1's pregnancy Observation → `http://hl7.org/fhir/us/core/StructureDefinition/us-core-observation-pregnancystatus` (its Pregnant `valueCodeableConcept` was already present — only the profile was wrong). Applied via `scripts/reattribute_cms69_profiles.py` (idempotent, formatting-preserving; 17 files, 1-line profile change each).
- **Scope guard**: only the 17 affected Observations were touched. 18 other CMS69 BMI-bearing cases (exclusions/exceptions/nominal num=0; BMI 15/17/18/30 etc. without a follow-up intervention) keep the `...screening-assessment` profile so their expected Numerator 0 is preserved; the 4 malformed `...observationcancelled` URLs are untouched.
- **Follow-up TODO (after verifying the 17 pass)**: 4 CMS69 Observations use the malformed profile URL `us-quality-core-observationcancelled` (missing hyphen; should be `observation-cancelled`) — `659f9c7b`, `8c89947a`, `a327cf96`, `ff09cf1e`, all LOINC `39156-5` `status cancelled`. They are excluded from the numerator by status today, so the malformed profile is latent; repair the URL for hygiene after the 17 verify 63/0.
- **Category**: resource / fixture data (data mis-attribution during conversion).
- **Verified (2026-09-04)**: engine re-run confirms CMS69 **63 / 0** (all 16 Numerator cases → 1, e25fc2f1 → 1). F-08 resolved.
