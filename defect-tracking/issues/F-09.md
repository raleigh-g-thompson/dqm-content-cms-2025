### F-09: CMS165/CMS135 test data mis-attributes BP & pregnancy Observations

- **Symptom**: CMS165 `6f37e357`/`f2d1fd7e` fail Numerator (exp 1, act 0); CMS135 `6a86918d` fails Denominator Exception (exp 1, act 0).
- **Root cause**: same class as F-08. CMS165 CQL retrieves `[USCore.BloodPressureProfile]` (LOINC `85354-9` with `8480-6` systolic / `8462-4` diastolic); the case's BP panel Observation was profiled `us-quality-core-observation-screening-assessment`. CMS135 CQL retrieves `[USCore.ObservationPregnancyStatusProfile]`; `6a86918d`'s pregnancy Observation (LOINC `82810-3`, SCT `77386006` Pregnant) was profiled the same way. The engine matches only the exact declared US Core profile, so the retrieves were empty.
- **Fix (applied 2026-09-04)**: re-attributed the 2 BP panels → `http://hl7.org/fhir/us/core/StructureDefinition/us-core-blood-pressure`; `6a86918d`'s pregnancy Observation → `http://hl7.org/fhir/us/core/StructureDefinition/us-core-observation-pregnancystatus` (its Pregnant `valueCodeableConcept` was already present). Applied via `scripts/reattribute_uscore_profiles.py` (idempotent, formatting-preserving; 1-line profile change each).
- **Verified (2026-09-04)**: engine re-run confirms all 3 cases recover (CMS165 Numerator, CMS135 Denominator Exception). F-09 resolved.
- **Category**: resource / fixture data (data mis-attribution during conversion).
